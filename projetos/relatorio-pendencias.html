Relatório de Pendências por E‑mail

Resumo automático, por e-mail, das tarefas que os técnicos finalizaram com alguma pendência. Cada cliente escolhe quem recebe e com que frequência: diário, semanal ou mensal.

Meu papel
Projeto inteiro, do motor ao painel

Gestores dos clientes da Auvo

Node, React, Prisma, Resend
Experimente: escolha a frequência, adicione destinatários, mude o horário e veja o e-mail que seria enviado. Dados fictícios

    Assunto Para

    O problema

    O resumo de pendências já existia como um fluxo no n8n, mas era tudo ou nada: para parar os e-mails de um cliente era preciso desligar o fluxo inteiro, as frequências não tinham destinatários próprios e o texto digitado pelos técnicos ia para o e-mail sem tratamento. Levei o relatório para dentro do portal do time, com configuração por cliente.

    O que construí

    • Motor que lê as tarefas finalizadas na API da Auvo e conta como pendência a observação deixada pelo técnico ou a pergunta do questionário sem resposta. Cada tarefa conta uma vez, agrupada por técnico.
    • E-mail em HTML e em texto puro, com totais, tabela por técnico e as pendências de cada tarefa com link para o detalhe no Auvo. Tudo que o técnico digitou é escapado, para ninguém conseguir montar um link falso num e-mail assinado pela Auvo.
    • App no portal do cliente: um cartão por frequência, cada um com seus destinatários (até 20) e horário. Pausar mantém a configuração salva.
    • Painel interno para o time ativar o app por cliente, com busca, ordenação e a data do último envio. Ativar não dispara nada: o cliente precisa configurar os destinatários antes.

    Decisões técnicas

    • Um job de hora em hora decide o que está na hora de sair. A data do último envio só é gravada depois que o provedor confirma, então uma falha é repetida no ciclo seguinte e o mesmo período nunca sai duas vezes.
    • Os períodos são sempre fechados (ontem, a semana de segunda a domingo, o mês anterior) e calculados no fuso de São Paulo.
    • A leitura da API tem teto de páginas, porque a API cobra por registro. Se o teto for atingido, o e-mail avisa que os números são parciais em vez de mostrar um total menor sem explicação.
    • Cada cliente roda isolado: se a API falhar para um, os outros continuam.
    • Tirei um botão de "enviar agora" que eu mesma tinha criado, porque deixava uma rota capaz de mandar e-mail para destinatários reais.

    Stack

    TypeScript, Node com Express, Prisma e PostgreSQL, React 18 com TanStack Query e Tailwind, API REST da Auvo, Resend para o envio, testes com Vitest e um script de ponta a ponta que gera o HTML sem precisar de banco.
